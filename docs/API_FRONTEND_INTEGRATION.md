## Совместимость и изменения

Действующие URL и поля сохранены. Новая GET-ручка позволяет перечитать разбор
по ID, не вызывая модель. `HotelierAnswer` включает исходный текст, extraction,
pending/confirmed/rejected, дату и признак симуляции.

Подтверждение всегда возвращает `answer_id`, `status`, `idempotent`,
`observation_ids`, `conflicts`, `source_type`, `question`. Повтор одинакового
решения возвращает те же ID уже созданных фактов, не пустую заглушку и не новые
наблюдения. `question` показывает текущее состояние уточнения, которое может
измениться после новых ответов. Отклонение возвращает пустые ID и `source_type=null`.

В `SearchResponse` добавлен `balance` с фактически использованным значением.
`ranking_method`, `include_simulated`, веса и группы
`matched / needs_verification / excluded` сохранены. Тексты и схематизация
`ParsedHotelQuery`, `ReplyExtraction`, `Observation` не заменялись другим форматом.

Важные уточнения для клиентов:

- `accept` — именно JSON boolean, строки `"yes"`/`"true"` и числа отвергаются.
- Несовместимое повторное подтверждение теперь 409 вместо общего 422.
- Недоступность гостевой модели/ключа/сети теперь 503 вместо общего 502.
  Невалидный результат модели по-прежнему 502. `QueryParserUnavailable`
  наследует `ParserError`, чтобы существующие ML-обработчики ошибок продолжали работать.
- Неизвестный доменный объект — 404. Случайный программный `KeyError` не
  классифицируется как «отель не найден».
- Новые поля добавлены к ответам, поле `detail` ошибок не удалено.

## Единая форма ошибок

```json
{"code": "state_conflict", "detail": "Решение уже принято; создайте новый ответ"}
```

| HTTP | code | Значение |
|---|---|---|
| 403 | forbidden | Локальный кабинет/симуляция отключены |
| 404 | not_found | Нет отеля, вопроса, ответа, свидетельства или конфликта |
| 409 | state_conflict | Действие противоречит уже сохранённому решению |
| 422 | invalid_request | Неверные поля, типы, веса, неполный разбор |
| 502 | invalid_model_output | Невалидный контракт/вывод модели |
| 503 | service_unavailable | Пустая необходимая БД либо недоступны сервис, модель, ключ, квота |

У ошибок Pydantic `detail` остаётся списком объектов `loc/msg/type/...`, а у
доменных ошибок — строкой. Необработанные ошибки программы остаются 500;
они не превращаются в 409/503 или успешную пустую выдачу.

Frontend `APIError` наследует прежний `RuntimeError`, содержит `status_code`,
`code`, `detail`. Старый ответ без `code` тоже читается. Текущий UI продолжает
использовать общий обработчик ошибок и не подтверждает действие после сбоя.
Схемы известных ошибок объявлены в OpenAPI для маршрутов API.

## Сценарий из интерфейса

1. Выполните поиск, при необходимости включите симулированные ответы.
2. Во вкладке «Отельер · демо» подтвердите ответ о конкретном номере,
   затем противоположный ответ о том же номере. Вопрос снова потребует уточнения.
3. В блоке «Противоречия» отображаются обе версии: значение, источник, цитата,
   дата, срок действия и достоверность. Отель и номер относятся к выбранному вопросу.
4. Явно выберите версию и заполните причину. Изначально ничего не выбрано;
   кнопка недоступна без выбора или с пустой причиной.
5. Нажмите «Сохранить решение». Очередь и история перечитываются, предыдущий
   поиск автоматически повторяется со структурированным запросом, без нового
   обращения к гостевой модели. Метод ранжирования, веса, balance и симуляция сохраняются.

Если остались другие противоречия, pending или устаревшие данные, вопрос не
выдаётся за закрытый. История обеих версий остаётся доступной.
Факт `false` не путается с неизвестностью. Симулированные данные не включаются
в обычный поиск автоматически.

Если решение сохранилось, но повторный поиск упал, UI сообщает это отдельно и
убирает старые карточки. Ошибка обновления не означает откат сохранённого решения.
При 409 не показывается ложное сообщение об успешном сохранении.
При изменении текста/вопроса или ошибке разбора старый предпросмотр по-прежнему сбрасывается.

Тогда логика кабинета была в Streamlit (`frontend/hotelier_view.py`, удалён 29.10.2026).
Сейчас тот же контракт использует React: `web/src/data/api/` (см. `web/README.md`).
JSON-снимки контракта в `docs/examples/` по-прежнему обновляются по текущему API.
