# Общая конфигурация модели и роли команды

`config/models.yaml` — единственный общий источник настроек модели. Он хранится
в Git, поэтому после pull команда получает те же параметры, что и ML-участник.
По умолчанию включены `parser_mode: ollama` и `model_name: gemma3:12b`.

## Что меняет ML-участник

- `config/models.yaml`: режим, имена локальной/облачной модели, температура,
  лимит выходных токенов, контекст Ollama, таймаут и reasoning effort Groq.
- `app/ml/prompts.py`: инструкции и примеры. Веса модели здесь не обучаются.
- `data/evaluation/`: запросы и разметка; `scripts/evaluate_parser.py` и
  `scripts/benchmark_models.py`: оценка без запуска сайта.
- `app/ml/ranking.py`, `app/ml/multicriteria.py`: формула подбора.

`app/core/model_config.py` читает YAML и проверяет типы/диапазоны/неизвестные поля.
`app/core/config.py` объединяет общие настройки с локальными адресами и секретами.
`app/ml/query_parser.py` передаёт параметры выбранному провайдеру. После изменения
YAML перезапустите backend; автоматического перечитывания во время запроса нет.

## Что остаётся локальным

`.env` не отправляется в Git. В нём адрес `OLLAMA_URL`, ключи `GROQ_API_KEY` и
`OPENAQ_API_KEY`, адреса API/БД и другие настройки окружения. Ключи нельзя писать
в YAML. Веса модели тоже не входят в репозиторий: их хранит Ollama.

Для разработки интерфейса без LLM допускается явный `PARSER_MODE=offline` в `.env`
или окружении процесса. Приоритет режима: окружение процесса → `.env` → YAML.
Чтобы вернуться к общему режиму, удалите это переопределение и перезапустите API.
`fixture` означает только готовые примеры; `offline` — разбор правилами.
Ни один из них не является нейросетью. При ошибке Ollama скрытого fallback нет.

Старые `MODEL_NAME`, `GROQ_MODEL`, `PARSER_TIMEOUT_SECONDS`, `OLLAMA_NUM_CTX`
больше не читаются из окружения: перенесите индивидуальные значения в общий YAML
через согласованное изменение и удалите старые строки из `.env`.
Старый `PARSER_MODE=offline` продолжит действовать, пока его явно не удалить.

## Запуск командой

Установите Ollama, запустите его и один раз загрузите модель из YAML:

```bash
ollama pull gemma3:12b
python -m scripts.seed_demo
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Backend/frontend-участник отвечает за запуск API и интерфейса. ML может отдельно
проверить модель, не поднимая сайт:

```bash
python -m scripts.evaluate_parser --mode ollama
python -m scripts.benchmark_models --profiles local-gemma12b --run --limit 3 --interval 0
```

Профили сравнения в `data/evaluation/model_candidates.json` намеренно выбирают
другие имена моделей для экспериментов. Это не конфигурация работающего сайта.
Отчёты оценивания сохраняют общие параметры и хеш YAML для воспроизводимости.

Для Docker YAML включается в образ; после правки нужен `docker compose up --build`.
Ollama работает отдельно на хосте. `DOCKER_OLLAMA_URL` задаёт адрес, доступный backend
из контейнера (по умолчанию `http://host.docker.internal:11434`). Адрес `127.0.0.1`
внутри контейнера указывает на сам контейнер. Не публикуйте Ollama в интернет;
для общего сервера нужен контролируемый доступ. Docker-запуск не устанавливает веса.

При переносе проекта архивом папка `config/` также включается в пакет.
