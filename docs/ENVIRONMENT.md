# Среда вокруг отеля: NoiseModelling и OpenAQ

Обновлено 26 октября 2026. Рабочая территория — прибрежный Адлер.
Вкладка «Среда вокруг отеля» читает отдельные отчёты через API. Они пока не
участвуют в ранжировании: станция поблизости не является датчиком в гостинице,
а учебный акустический сценарий не является измерением настоящего шума.

## Уже работает

**OpenAQ v3:** поиск стационарных станций PM2.5 в радиусе 25 км, расстояние,
station_id и sensor_id, запрос 168 завершённых часов, проверка времени/единиц,
свежести и полноты. Час принимается при >=75% внутреннего покрытия; станция —
при >=75% пригодных часов за весь период и последнем измерении не старше 48 часов.
Это политика MVP, не норматив AQI. Проверяются 10 ближайших станций; выбирается
ближайшая пригодная, ограничение выборки видно в отчёте. Пропуски не равны нулю,
дубли не увеличивают полноту, конфликтующие часы исключаются.

Сохраняются даты, координаты, расстояние, поставщик, доступные сведения о лицензии,
единицы и среднее по пригодным часам. Нет ключа / нет станций / нет пригодной
станции / ошибка API — разные статусы. HTTP-бюджет: 30 вызовов, проверка дедлайна
60 секунд перед каждым вызовом, timeout отдельного вызова 20 секунд. Кэш старше
6 часов явно отмечается как устаревший. Используем официальный HTTP API через
существующий httpx, не старый пакет py-openaq.

**NoiseModelling 5.0.1:** реальный внешний Java CLI. Python подготавливает OSM
в EPSG:32637, контуры зданий, дороги, точки у фасадов с отступом 2 м и шагом до
10 м, на заданных высотах. Движок считает распространение, отражения и дифракцию.
Сохраняются D (06–18), E (18–22), N (22–06), DEN. Это периоды выбранного сценария,
не заявление о соответствии российским нормативам. Расчёт ограничен 500 м.

У точек есть индекс стены, азимут, высота, соседние источники. Поле
`planar_obstacles` — только пересечение прямого луча со зданиями; акустический
результат вычисляет Java. Контур определяется по OSM ID или единственному полигону,
содержащему точку отеля. Вторая привязка помечена как непроверенная человеком.
Реальные окна и номера по этим точкам не восстановлены, дворовые фасады пропущены.

## Что проверено именно для Адлера

Выгрузка OSM от 25 октября: **15 842 объекта**, исходный запрос, bbox, дата,
атрибуция и лицензия внутри `data/environment/osm_buildings.json`. Область на
~1 км шире hotel bbox, чтобы собирать препятствия около границ.

Подготовлены **295 фасадных точек у 24 из 25 отелей** на высоте 4 м. У Center Plaza
нет однозначной привязки к зданию. Все обычные отчёты имеют `needs_data`:
интенсивности движения отсутствуют, высоты многих зданий неизвестны. Например,
вокруг «Островка» 1111 контуров и ни у одного нет пригодного тега `height`.

Реальный запуск движка выполнен для «Островка»: **26 точек на высотах 4 и 7 м,
104 строки D/E/N/DEN**. Однако это **учебный сценарий на реальной геометрии**:
отсутствующие высоты приняты равными 9 м, на каждой дороге 100/50/10 легковых
авто/час D/E/N, скорость 30 км/ч, остальные категории транспорта — нули. Эти
числа НЕ получены в Адлере. В `adler_scenario.json` сохранено `scenario=true`.

Остаются допущения: плоская земля, стандартные грунт/погода движка, непроверенная
полнота OSM. **Авиация, железная дорога и бары акустически не моделируются**;
rail/nightlife могут быть в диагностике. Для Адлера авиация особенно существенна.
Дорожный шум нельзя выдавать за общую тишину или за звук внутри номера.

OpenAQ допускает координаты Адлера, но **наличие пригодных станций пока не
подтверждено: личного API-ключа нет**. `not_configured` не означает «станций нет».

## Запуск

Сохранённые отчёты без сети/Java:

```bash
python -m scripts.seed_demo --environment
uvicorn app.main:app --host 127.0.0.1 --port 8000
# Отчёты среды по отелю (экрана в React пока нет; Streamlit удалён 29.10.2026):
curl http://127.0.0.1:8000/api/hotels/<HOTEL_ID>/environment
```

Повторный seed идемпотентен и не обновляет даты старых данных. История отчётов
хранится в SQLite `environment_reports`; основные observations не меняются.

Живой OpenAQ: получить ключ https://explore.openaq.org/register, записать
`OPENAQ_API_KEY` в локальный `.env`, перезапустить backend, нажать «Обновить данные
OpenAQ». Ключ не следует публиковать. Альтернатива кнопке:

```bash
python -m scripts.environment air --hotel-id osm:node:10058556917
```

Подготовка и запуск акустики:

```bash
python -m scripts.collect_environment_osm
python -m scripts.environment prepare-noise --all
python -m scripts.install_noisemodelling
```

Installer скачивает официальный CLI (~90 МБ), проверяет закреплённый SHA256.
Установите Java 17 и задайте в `.env` абсолютные пути `NOISEMODELLING_HOME`
(NoiseModelling_without_gui-5.0.1) и `NOISE_JAVA_HOME` (каталог с bin/java).
На текущем Mac обе программы уже скачаны внутри runtime/tools; системная Java
не изменялась. Бинарники не входят в Git/архив исходников.

```bash
python -m scripts.environment run-noise --hotel-id osm:node:10058556917 --scenario --heights 4 7
```

Для собственного трафика: вместо `--scenario` передать `--traffic traffic.json`
и обеспечить высоты всех выбранных зданий. JSON: ключи osm:way:ID, значения —
source_ref и 30 чисел. Для каждого D/E/N и LV/MV/HGV/WAV/WBV нужны
`<класс>_<период>` (авто/час) и `<класс>_SPD_<период>` (км/ч).
Нужны все дороги и все поля; обоснованные нули допустимы. source_ref сам по себе
не доказывает достоверность данных. Даже такой расчёт имеет оставшиеся допущения
о земле/погоде/источниках и помечается `modeled`, не измерением.

Каждый запуск: runtime/noise_runs/ID/{input.json,engine.log,levels.json,report.json}
и своя H2 DB; в отчёте версия и SHA256 входа. Ограничения: 5 минут, 1 ГБ heap,
2 потока. Произвольный запуск Java не открыт через HTTP.

## Проверки и ответственность

Обычный `pytest` использует синтетические ответы OpenAQ. Настоящий движок:

```bash
ADLER_TEST_NM_HOME=/absolute/path/NoiseModelling_without_gui-5.0.1 \
ADLER_TEST_JAVA_HOME=/absolute/path/java-home \
python -m pytest -s tests/test_noise_engine.py
```

На синтетической геометрии подтверждены +10 дБ при десятикратном потоке и
снижение около 13.3 дБ после добавления здания-препятствия. Это проверка механизма,
не калибровка или натурная проверка в Адлере.

У2: noise.py, air_quality.py, OSM collector, Groovy и geo-тесты. У3: service.py,
API, storage, конфигурация, installer/CLI/seed. У4: environment_view.py и UI-тесты.
У1: будущая проверенная политика включения новых фактов в ранжирование.
Погода/климат и видимость моря пока не реализованы.
