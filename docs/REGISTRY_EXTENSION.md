# Этап 6: расширение через реестр

Выполнен 29.10.2026 в корневом `hack-o`; вложенная `Островок/` при реализации
не изменялась, позже удалена по запросу владельца при очистке.
В [основной YAML](../app/features/registry.yaml) добавлен `blackout_curtains`:
«Плотные шторы», boolean, scope `room`, provider `hotelier`, TTL 180 дней,
вес 0.5, шаблон вопроса и синонимы, включая «плотных штор» для отрицательного ответа.
Всего в реестре 7 характеристик.

## Что подключается автоматически

API `/api/features`, список свойств кабинета, вопросы, сохранение наблюдений,
конфликты, evidence и оба метода ранжирования используют существующие механизмы.
Специальных ветвлений для штор в агенте, хранилище и ранжировании нет.

Гостевой промпт теперь передаёт также `description` и `aliases` из реестра.
Гостевые и ответные адаптеры Ollama/Groq получают актуальные ключи в JSON-схеме.
Контракты frontend/ML и URL остались прежними: новое свойство передаётся через
`feature_key`, значение — boolean. Rules-парсер дополнительно ищет синонимы
по границам слов: «неплотные шторы» и «антиблэкаут» отправляются на уточнение.

Для автономной интеграции добавлен один явный запрос
«Нужен номер с плотными шторами» в [demo fixtures](../data/demo/query_fixtures.json)
и два ответа в [reply fixtures](../data/demo/hotelier_reply_fixtures.json).
Теперь доступно 13 demo-запросов и 6 fixture-ответов.
Fixture остаётся точным словарём; произвольные формулировки требуют уточнения.
Исходный evaluation-набор из 44 случаев (12 demo/32 held-out) не менялся;
новый сценарий служит проверкой интеграции, отдельная оценка качества NLP не проводилась.

## Как проверить вручную

1. После изменения YAML перезапустите backend: реестр кэшируется в процессе.
   Выполните `python -m scripts.seed_demo`, чтобы сохранить актуальные определения
   в БД. Seed идемпотентен и не удаляет ответы. Новая миграция не нужна;
   схема остаётся `0003_question_lifecycle`.
2. В существующем UI выберите «Нужен номер с плотными шторами» и включите
   «Учитывать симулированные ответы». Пока сведений нет, подходящих номеров нет;
   агент создаёт вопросы отельерам.
3. В кабинете выберите отель и «Плотные шторы». Разберите ответ
   «В номере 501 есть плотные шторы.». До подтверждения он остаётся pending.
4. Подтвердите: поиск обновится, появится выбранный отель с номером 501.
   Затем подтвердите «В номере 502 нет плотных штор.» — номер 502 не подходит.
5. В evidence проверьте отдельные наблюдения, исходные цитаты, TTL и источник.
   Перезапуск backend сохраняет ответы и результаты.

Утверждения симулятора имеют источник `hotelier_simulated`, статус `estimated`,
confidence `low`; обычный поиск их исключает. Подтверждение удостоверяет разбор,
а не фактическую светонепроницаемость штор. Шторы в 501 и вид на море в 502
не образуют один подходящий номер. Противоречивые ответы открывают обычный
конфликт и вопрос; явное решение учитывается существующим resolver.
