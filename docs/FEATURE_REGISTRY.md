# Реестр характеристик

Источник истины — `app/features/registry.yaml`; загрузка и валидация — `registry.py`.
Значения типов/единиц/scope проверяются как для запросов, так и для наблюдений.

| Ключ | Тип / scope | Provider | TTL | Вес по умолчанию |
|---|---|---|---|---|
| walking_distance_to_beach_m | number m / hotel | pedestrian_distance | 90 дней | .8 |
| quietness_proxy | low/medium/high / hotel | quietness | 90 дней | .9 |
| nightlife_distance_m | number m / hotel | nightlife_distance | 60 дней | .7 |
| sea_view | boolean / room | hotelier | 90 дней | .6 |
| soundproofing | boolean / room | hotelier | 180 дней | .7 |
| sunset_view | boolean / room | hotelier | 90 дней | .6 |
| sea_view_potential | none/partial/wide / hotel | viewshed | 180 дней | .6 |
| sea_view_min_floor | number floor / hotel | viewshed | 180 дней | .4 |
| sunset_view_potential | none/seasonal/year_round / hotel | viewshed | 180 дней | .6 |
| sunset_view_min_floor | number floor / hotel | viewshed | 180 дней | .4 |
| aircraft_noise_exposure | low/medium/high / hotel | aircraft_noise | 365 дней | .8 |
| aircraft_path_distance_m | number m / hotel | aircraft_noise | 365 дней | .7 |

Quietness: дороги motorway/trunk=1, primary=.9, secondary=.7, tertiary=.5,
residential=.3, service=.15, unclassified=.4; decay scale=120 м.
Rail=1, scale=180 м; nightlife=.6, scale=100 м. Максимум из `w*exp(-d/scale)` — risk.
High quietness при risk<.25, medium при <.6, иначе low. Это экспертная некалиброванная эвристика.

`nightlife_distance_m` — по прямой в локальной проекции, до ближайшего **известного** заведения;
не пеший путь. Отсутствие заведений в данных даёт unknown, не «баров нет».
`sea_view`/`sunset_view`/`soundproofing` — утверждения отельера о конкретных номерах.
Расчётные `*_potential`/`*_min_floor` относятся к зданию целиком: «с какого этажа и с какой стороны
в принципе видно». Номера комнат и реальные окна модель не знает — это и есть вопрос отельеру.

## Viewshed (`app/geo/viewshed.py`, provider `viewshed`)

1. Поверхность: рельеф Copernicus GLO-30 после морфологического открытия 5×5 (~150 м), чтобы убрать
   дома/деревья, частично попавшие в DSM; плюс контуры зданий OSM на сетке 2 м.
   Высота здания: `height`, иначе `(building:levels + roof:levels) × 3 м`, гаражи/навесы 3 м.
2. Море: части рамки справа от OSM `natural=coastline` (в OSM суша слева); сетки 10 м у отелей и 30 м дальше.
3. Точки фасада: каждые 12 м по внешним стенам, 1 м наружу по нормали; стены вплотную к соседу пропускаются.
   Глаза: земля + 1.6 м + 3 м × (этаж − 1). Этажность отеля из OSM, иначе допущение 3 этажа (флаг).
4. Лучи: сектор окна ±60° от нормали, шаг 1°, до 20 км (шаг 2 м → 6 м → 30 м).
   Кривизна Земли с рефракцией k=0.13. Точка видна, если её угол выше всех более близких.
5. Море: доля лучей сектора с видимой водой. ≥25% — `wide`, ≥3% — `partial`.
   `sea_view_min_floor` — первый этаж, где хоть на одном фасаде ≥3%.
6. Закат: солнце NOAA (`app/geo/solar.py`) на 15-е число каждого месяца, участок пути ниже 6°.
   Месяц засчитан, если центр диска выше горизонта при высоте ≤ 3° с запасом ±1° по азимуту
   (просвет ≥ 3°). «Садится в море» — виден до ≤ 1° и горизонт на этом азимуте — морской.
   ≥10 месяцев — `year_round`, иначе `seasonal`.
7. Достоверность: неизвестные высоты соседей перебираются в трёх сценариях (3 / 6.5 / 12 м).
   Если категории моря и заката совпадают во всех и этажность отеля из OSM — `medium`, иначе `low`.
   В evidence: сценарии, сводка по этажам, лучшая точка фасада, ID зданий, закрывающих горизонт,
   SHA256 входов и человекочитаемый `summary` («Закат из окон стороны З, с 2-го этажа, апрель–август»).

## Авиашум (`app/geo/aircraft.py`, provider `aircraft_noise`)

ВПП 06/24 и 02/20 аэропорта Сочи из OSM. От каждого торца — прямая по продолжению оси, глиссада 3°,
порог на 15 м, 12 км. Тот же профиль для взлётов (консервативно: реальный набор круче).
Наблюдатель на 10 м над землёй (DEM). Кратчайшее наклонное расстояние до траектории или до ВПП:
< 800 м — `high`, < 2 км — `medium`, иначе `low`. Пороги — по ориентиру Lmax A320 ~85–90 дБА на 300 м
и −6 дБ на удвоение; дБ не выдаются. Все отели выборки в 0.1–1.2 км от траекторий: Адлер под заходом на 06.

Не моделируются: деревья, балконы и козырьки, самозатенение сложного контура своего здания,
реальные окна и планировка номеров. DEM снят в 2011–2015 гг.

## Добавление без изменения Python-кода

Добавьте в YAML (и перезапустите backend):

```yaml
blackout_curtains:
  label: Плотные шторы
  description: Утверждение отельера о конкретном номере
  type: boolean
  scope: room
  unit: null
  provider: hotelier
  ttl_days: 180
  default_weight: 0.5
  aliases: [плотные шторы]
  question: В каких конкретных номерах есть или нет плотных штор?
```

Характеристика появится в `/api/features` и кабинете. Ответ «В номере 501 есть плотные шторы»
разбирается существующим provider, сохраняется после confirmation. Structured search принимает новый ключ;
Ollama получает обновлённый реестр. Для offline fixture-парсера добавьте отдельный явный пример запроса:
он сознательно не интерпретирует произвольный текст. Новый provider по имени сам не запускается — нужен whitelist.

Расширение этим способом проверено `tests/test_feature_agent.py`. Для нового способа вычисления
необходим реальный calculator, его ToolSpec и тесты; текст YAML не создаёт геоданные.
Пример такого calculator — `viewshed` (выше): четыре YAML-ключа + один provider.
