# Фактические проверки MVP

Проверено 24 октября 2026 года на macOS arm64, Python 3.13.5. Результаты относятся к сохранённому
срезу OSM от 23 октября 2026 года и текущему коду. Это результаты запусков, а не план тестирования.

## Установка и сервисы

- В новой `.venv` выполнено `python -m pip install -e '.[geo,test]'`; установка завершилась успешно.
- Установленные версии закреплены в `requirements.lock`; `python -m pip check` → `No broken requirements found`.
- `python -m scripts.seed_demo` → 25 отелей, 75 наблюдений. Повторный seed сохраняет ответы отельера.
- Uvicorn запущен на `127.0.0.1:8000`; HTTP health → `status=ok`, `database=ok`, `hotels=25`, `parser_mode=fixture`.
- Streamlit запущен на `127.0.0.1:8501`; `/_stcore/health` → `ok`.
- Внешние сервисы не выдаются за проверенные в health: `external_services_checked=false`.

Запуск интерфейса после установки не требует Overpass, Ollama или сети. Онлайн-подложка карты опциональна.
Первичная установка зависимостей требует интернета; lock собран на указанной платформе.

## Автоматические тесты

Команда: `python -m pytest -q --junitxml=docs/examples/pytest_results.xml`.
Фактический итог: **40 passed, 0 failed, 0 errors, 0 skipped**, 2.173 секунды в этом запуске.
Машинный отчёт: [pytest_results.xml](examples/pytest_results.xml).

Проверяются:

- парсер: единицы, отрицания, неизвестные запросы, строгие типы, JSON Schema/options Ollama,
  две попытки при испорченном JSON и неверной структуре HTTP-ответа;
- evaluator: неверный оператор учитывается как ошибка, недоступная модель остаётся в знаменателе,
  булево отрицание не считается числовым нулём;
- Geo: реальный обход вместо прямой, отсутствие пути, слишком далёкая привязка, закрытый проход,
  пересечение известного барьера, private/foot=no, неполный ответ Overpass;
- достоверность: TTL, будущие наблюдения, симуляции, конфликты и сохранение обеих версий;
- ranking: hard/soft, unknown, нулевые веса, смена порядка от весов, условия в одном номере;
- агент: выбор источника, настоящие локальные вычисления при пропуске Geo-факта, whitelist/бюджет,
  добавление `blackout_curtains` через YAML с существующим hotelier provider;
- отельер: диапазоны номеров, отрицания/этаж, неоднозначность, частичный разбор, подтверждение,
  идемпотентность, конфликт и исключение симуляции из обычного поиска;
- API: сквозной поиск и ошибки, устойчивость seed;
- UI: экранирование OSM-текста, Streamlit AppTest проходит поиск → ползунок → ответ → подтверждение.

В тестах запрещено подключение к внешней сети; база отдельная, в памяти. Часы для TTL фиксированы
относительно даты snapshot, чтобы тесты старых данных оставались воспроизводимыми. Рабочее приложение
использует настоящие часы: истёкшие факты перестают участвовать в подборе.

Осталось одно предупреждение зависимости Starlette: TestClient использует совместимость с `httpx`,
которую библиотека пометила устаревшей. Проверки проходят; переход тестового транспорта на `httpx2`
нужно выполнить при обновлении зависимостей. Предупреждение не скрывается.

## Данные и маршруты

Команда: `python -m scripts.validate_data`.
Машинный отчёт: [quality_report.json](../data/demo/quality_report.json).

- 25 уникальных отелей совпадают с выборкой сырого OSM snapshot; вымышленных объектов нет.
- 4895 исходных OSM-элементов, граф: 12 188 узлов и 27 002 ребра.
- SHA256 сохранённого GraphML совпадает с metadata.
- Все 75 наблюдений повторно вычислены и совпали с сохранёнными, включая evidence и исходные даты.
- Пешеходный путь рассчитан для 23/25 отелей — покрытие 92%.
- Для «Грант» привязка к графу слишком далека; для «Три Сезона» пути нет. Значения остаются unknown.
- У 73 наблюдений confidence=low, у 2 unknown. Числовая вероятность не выдумывалась.

Эти проверки подтверждают происхождение и воспроизводимость. Они **не измеряют точность относительно
полевого обследования**. Входы/проходимость на местности не проверены, `ground_truth_accuracy=null`.
Quietness — proxy по OSM, без авиационного шума и акустических измерений; авиашум — отдельная характеристика.

## Офлайн-разбор свободного текста (`PARSER_MODE=offline`)

Команда: `python -m scripts.evaluate_parser --mode offline` →
[отчёт](../data/evaluation/parser_metrics_offline.json); первый прогон сохранён в
[parser_metrics_offline_first_run.json](../data/evaluation/parser_metrics_offline_first_run.json). Правила писались без просмотра held-out.

| Прогон | held-out exact | precision | recall | F1 | операторы |
|---|---|---|---|---|---|
| Первый, до просмотра ошибок | 0.41 | 0.63 | 0.67 | **0.65** | 8/18 |
| После исправления общих ошибок | 0.72 | 0.94 | 0.95 | 0.95 | 17/18 |

Честная оценка — первая строка. Вторая оптимистична: исправления (запятая в «1,2 км», диапазоны,
несколько чисел, «ровно», числа словами, «не нужен» = не учитывать, «обязателен», явные веса,
«по прямой», брони/аптеки как неподдерживаемое) делались после просмотра ошибок held-out,
хотя и как общие правила. Оставшиеся расхождения спорные: «вид из окна» без уточнения,
«не на закат» как строгое условие. Для новой независимой оценки нужна свежая разметка.
Демо-набор: 14/14. Тесты правил — `tests/test_rules_parser.py`, формулировки свои, не из эталона.

из распакованного кода создана отдельная SQLite, seed выполнен дважды, поиск вернул 12/2/11,

демо-поиск использовал только с явным флагом. Для этой проверки использована уже установленная

Все локальные ссылки актуальной документации проверены. Последующая перепаковка добавила
только этот абзац отчёта; проверенный код и данные не менялись.

Визуальная проверка браузером не выполнена: инструмент управления браузером недоступен

вёрстки/скриншоты. Нужен просмотр интерфейса человеком или настроенным браузерным тестом.
