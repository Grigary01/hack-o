# Начните здесь — комплект для coding-агента и команды

Это **план и инструкции**, а не исходный код готового приложения.

1. `PROMPT_CODING_AGENT.md` — **главный промпт**. Отправьте его полностью в Claude Code / Codex / другой coding-агент, у которого есть доступ к рабочей копии репозитория.
2. `ARCHITECTURE.md` — технический план: два pipeline (сбор фактов и поиск), ML/Geo/Backend/UI контракты, хранение достоверности и расширяемость.
3. `TEAM_TASKS.md` — четкое распределение файлов и задач между ML, Geo/Data, Backend/Agent, Frontend и QA.
4. `CODE_SKETCH.md` — наброски Python-интерфейсов, структур данных и тестов для согласования кода между участниками.

## Исходный репозиторий

<https://github.com/MaximShalankin/agent_tool_map>

Нужен git clone/fork в собственный рабочий каталог. Оригинальная лицензия MIT — сохраните LICENSE и attribution.

## Пример старта

```bash
git clone https://github.com/MaximShalankin/agent_tool_map.git
cd agent_tool_map
git switch -c feature/ostrovok-adler-mvp
```

Затем положите эти Markdown-файлы в проект (например, под `planning/`), откройте папку в coding-агенте и отправьте `PROMPT_CODING_AGENT.md`.

## Что агент должен сделать прежде, чем писать всю систему

- Прочитать реальный исходный код, сверить исходный аудит с содержимым.
- Создать в репозитории документацию `docs/` с деревом файлов и API-контрактами.
- Договориться о JSON-схеме между ML/Backend/Frontend.
- Сделать работающий P0 вертикальный сценарий на маленьком наборе проверенных данных.
- Не выдавать геодезическое расстояние за пешее и фиктивный ответ отельера за реальный факт.

Демо-регион: **прибрежный Адлер (Сочи), Россия**. Цель: 15–30 проверенных отелей и маленький прототип; географические границы уточнить после проверки покрытия OSM.
