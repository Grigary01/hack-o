# web — React-фронтенд «Островок · Демо подбора»

Фронт по макету `docs/design/Untitled.pdf`: поиск по пожеланиям, выдача с фильтрами и картой,
карточка отеля/номера и кабинет отельера от вопроса до опубликованного ответа.
Это единственный интерфейс проекта: прежний Streamlit (`frontend/`) удалён 29.10.2026.

Стек: React 19, TypeScript, Vite, React Router, TanStack Query v5, CSS Modules + CSS-переменные.
Внешних UI-библиотек и картинок из PDF нет: иллюстрации номера и схема карты нарисованы SVG.

## Быстрый старт

Нужен Node.js ≥ 20.19 (проверено на 22 и 26).

```bash
cd web
npm ci
npm run dev:mock        # демо без бэкенда → http://localhost:5173
```

`npm run dev` тоже стартует в mock-режиме (значение по умолчанию в `.env.development`).

### С бэкендом (режим api)

В корне репозитория (отдельный терминал):

```bash
python -m scripts.seed_demo                                  # один раз: демо-база Адлера
PARSER_MODE=offline uvicorn app.main:app --port 8000         # без LLM; с Ollama — без PARSER_MODE
```

Затем:

```bash
cd web
npm run dev:api         # Vite проксирует /api → http://127.0.0.1:8000
```

Другой адрес бэкенда: `VITE_API_PROXY_TARGET=http://127.0.0.1:8765 npm run dev:api`
(или в `web/.env.local`, см. `.env.example`).

## Режимы данных: `VITE_DATA_MODE=mock|api`

Режим фиксируется **при сборке** (`vite --mode mock|api` или `VITE_DATA_MODE` в `.env*`); любое другое
значение останавливает сборку. Во время работы режим не меняется, и **ошибки API не подменяются моками**:
если бэкенд недоступен, экран показывает ошибку и кнопку «Повторить».

Режим виден в интерфейсе: плашка «Демо» / «Демо · API» в шапке и подпись в подвале.

```
src/data/
  types.ts            доменная модель UI и интерфейс DataSource — компоненты знают только её
  source.ts           единственная точка выбора адаптера по VITE_DATA_MODE
  hooks.ts            хуки TanStack Query (ключи, инвалидация после публикации ответа)
  api/contract.ts     DTO FastAPI (сверено с app/api, app/schemas и /openapi.json)
  api/mappers.ts      DTO → доменная модель; тексты для ключей registry.yaml
  api/source.ts       адаптер FastAPI
  mock/fixtures.ts    демо-данные (Батуми, цены, категории, blackout)
  mock/parseAnswer.ts демо-разбор ответа отельера по категориям номеров
  mock/source.ts      адаптер-симулятор с состоянием в sessionStorage
```

Компоненты не могут импортировать `data/mock/*` и `data/api/*` напрямую — это запрещено правилом ESLint.

### Что подключено в api-режиме

| Экран | Эндпоинты |
|---|---|
| Главная | `GET /api/demo-queries` |
| Выдача | `POST /api/search` (`include_simulated` = `demo_mode` из `/api/health`), `GET /api/features` |
| Карточка отеля | `GET /api/hotels/{id}` + результат поиска |
| «Запросить у отельера» | `POST /api/hotelier/questions` |
| Кабинет: вопросы | `GET /api/hotels`, `GET /api/hotelier/questions?hotel_id=&status=` (+ `context`: почему вопрос открыт) |
| Ответ → проверка | `POST /api/hotelier/questions/{qid}/answer`, `GET /api/hotelier/answers/{aid}` |
| «Подтвердить и опубликовать» / «Изменить ответ» | `POST /api/hotelier/answers/{aid}/confirm` (`accept: true/false`) |
| Результат публикации после перезагрузки | `GET /api/hotelier/answers/{aid}`, `GET /api/hotelier/conflicts?hotel_id=&status=open` |
| Характеристики | `GET /api/hotelier/hotels/{id}/facts` |
| Номера | `GET /api/hotels/{id}/evidence` (текущее знание уровня `room`) |

В api-режиме выдача — реальные отели Адлера из OSM, ответы отельера — номера комнат
(«В номерах 301–305 есть шторы blackout»), как того требует bounded-парсер бэкенда.
Ошибки API приходят как `{code, detail}`; `409 state_conflict` показывается как «состояние уже изменилось».

## Демо-сценарий (mock)

1. Главная → «Найти отели» (запрос из макета про blackout, магазин ночью и море).
2. Выдача: «Приморский» — условия подтверждены; «Тихий двор» — blackout «нет данных».
   «Источники» раскрывают основания; «Запросить и уведомить» отправляет вопрос отельеру.
3. «Посмотреть номер» → карточка номера, «На чём основан подбор». «Выбрать номер» честно сообщает,
   что бронирования нет.
4. Ссылка «Ответить за отельера» или «Кабинет отельера» → вопрос «Есть ли в номерах шторы blackout?» → «Ответить».
5. Ответ свободным текстом (пример — в подсказке поля) → «Проверить данные» → таблица разбора;
   «Есть · изменить» переключает значение строки → «Подтвердить и опубликовать».
6. «Характеристики обновлены» + «Как увидит гость». «Открыть выдачу как гость» — «Тихий двор» теперь в подтверждённых.

Состояния для показа:
- пустая выдача — направление не «Батуми»; «Все варианты скрыты фильтрами» — бюджет;
- ошибка — добавьте к адресу `?mockFail=search` (также `hotel`, `cabinet`, `publish`, `all`);
- неразобранный ответ — например «Возможно, летом повесим blackout»;
- сброс демо — «Обзор» в кабинете → «Сбросить демо».

## Docker

Всё приложение — бэкенд и React — поднимается из корня репозитория одной командой:

```bash
docker compose up --build
# React: http://localhost:8080   API: http://localhost:8000/docs
```

Сервис `web` собирается из `web/Dockerfile` (`VITE_DATA_MODE=api`), раздаёт статику через nginx
и проксирует `/api`, `/docs`, `/openapi.json`, `/health` в сервис `backend` (`web/nginx.conf`).
Порт меняется переменной `WEB_PORT` в корневом `.env`.

Только демо, без бэкенда:

```bash
docker build --build-arg VITE_DATA_MODE=mock -t ostrovok-web:mock web
docker run --rm -p 8082:8080 ostrovok-web:mock     # http://localhost:8082
```

`web/` не входит в контекст сборки образа бэкенда (allowlist в корневом `.dockerignore`).

## Что ждёт контракта бэкенда

Всё ниже в интерфейсе либо помечено как демо (mock), либо честно отключено (api).

| Возможность | Сейчас в API | Что показывает фронт |
|---|---|---|
| **Цены и тарифы** | нет полей цены | mock: «демо-цена», бюджет-фильтр; api: «Цены не подключены», фильтр бюджета выключен, на карте — номера вместо цен |
| **Бронирование** | нет эндпоинта | «Выбрать номер» показывает, что бронирование не подключено |
| **Направления кроме Адлера** (Батуми из макета) | `region` только `Adler`, иначе `needs_clarification` | mock: только Батуми; api: поле направления заблокировано |
| **Даты и гости** | `SearchRequest` их не принимает | mock: ночи и сумма; api: подпись «Пока не влияет на подбор» |
| **Категории номеров** («Улучшенный», «Стандартный») | только номера комнат (`room_number` = цифры) | mock: категории; api: «Номера 301–303» |
| **Blackout по категориям** | `blackout_curtains` есть в реестре (вопрос, поиск, разбор ответа), но только по номерам комнат | api: «Шторы blackout — есть в номере 301»; категории — только в mock |
| **«Магазин 24/7»** | есть `night_open_places_500m` (любые места, открытые в 01:00) и `nearest_night_pharmacy_m`, отдельного «магазина» нет | api: «Открыто ночью рядом — N мест» |
| **Время пешком** | только метры | фронт считает ≈ минуты при 80 м/мин |
| **Правка строки разбора** перед публикацией | `ConfirmRequest` = только `accept` | mock: «Есть · изменить»; api: «Изменить ответ» отклоняет pending и возвращает текст в редактор |
| **Черновики ответа** | нет | `localStorage` браузера, с подписью «сохранён в этом браузере» |
| **Фото к ответу** | нет загрузки | превью только локально + предупреждение, что не отправляется |
| **Уведомить гостя об ответе** | нет подписки | mock: «Запросить и уведомить»; api: «Запросить у отельера» (только вопрос) |
| **Авторизация отельера** | кабинет — симулятор в `DEMO_MODE`, без привязки к отелю | выбор отеля в боковой панели «демо без входа» |
| **Фото, адрес, звёзды, рейтинг отелей** | только OSM-теги | SVG-иллюстрации, подпись «фото не подключены» |
| **Карта с подложкой** | координаты есть, тайлов нет (офлайн-демо) | схема по координатам, море схематично |

Уже закрыто бэкендом: `blackout_curtains`, `GET /api/hotelier/answers/{id}`, фильтры очереди вопросов.

Есть в API, но пока не вынесено в этот UI: проверка расчётных фактов отельером
(`POST /api/hotelier/facts/review`), разрешение конфликтов оператором (`GET /api/hotelier/conflicts`,
`POST /api/hotelier/conflicts/{id}/resolve`),
веса пожеланий и `ranking_method`, отчёты среды (`/api/hotels/{id}/environment`). Пока они доступны только через API (Swagger `/docs`).

## Доступность и адаптивность

- Сетка 1440 px повторяет макет (фильтры 240 / выдача / карта 360; кабинет — меню 248 px).
  До 1180 px карта уходит над списком; до 860 px фильтры и карта открываются кнопками;
  на 390 px карточки компактные, таблица проверки превращается в карточки, меню кабинета — лента вкладок.
- Все поля подписаны (`<label>`), ошибки связаны через `aria-describedby`, сообщения о результате — `role="status"/"alert"`.
- Видимый фокус у всех интерактивных элементов, ссылка «Перейти к содержимому», при смене экрана фокус на `<main>`.
- Метки на карте — кнопки с понятным `aria-label`; статус условия дублируется текстом, не только цветом.
- Цвета текста из макета затемнены там, где не дотягивали до WCAG AA 4.5:1 (см. `src/styles/tokens.css`).
- `prefers-reduced-motion` отключает анимации.
