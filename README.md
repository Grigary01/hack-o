# О!дин шаг · прибрежный Адлер (трек «О!дин шаг до идеального отеля»)

Агентная система подбора отелей Адлера по характеристикам, которых нет в карточках: вид на море
и закат по этажам (рельеф + здания OSM), путь до пляжа по пешеходному графу, шум дорог, баров и самолётов,
с источником, датой и уверенностью у каждого значения, диалогом с отельером и объяснением выбора.

## Быстрый старт

```bash
git clone --branch frontend/mvp https://github.com/Grigary01/hack-o.git
cd hack-o
docker compose up --build
# React-интерфейс: http://localhost:8080
```

Ключи и LLM не нужны: в Docker по умолчанию `PARSER_MODE=offline` (свободный текст разбирается правилами).
Первая сборка — несколько минут (образы, Python-колёса, npm). Демо-данные уже лежат в репозитории,
загрузка OSM/DEM при старте не выполняется. Остановка: `Ctrl+C` или `docker compose down`;
`docker compose down -v` дополнительно удалит базу с ответами отельера.

Для модели вместо правил: `ollama pull gemma3:12b` на хосте и `DOCKER_PARSER_MODE=ollama` в `.env`
(`cp .env.example .env`); модель и параметры генерации — в `config/models.yaml`.

## Зависимости и переменные окружения

Ресурсы без inference: 2 CPU, 2 GB RAM, ~2.5 GB диска под образы.
Ollama работает отдельно: веса Gemma 12B занимают около 8.2 GB, память нужна дополнительно.

Сервисы в [`compose.yaml`](compose.yaml); порты слушают только `127.0.0.1`, меняются в `.env`:

| Сервис | Порт | Что это |
|---|---|---|
| `web` | **8080** (`WEB_PORT`) | React-фронт из `web/` (nginx); `/api/*`, `/docs`, `/openapi.json`, `/health` проксируются в `backend` |
| `backend` | 8000 (`BACKEND_PORT`) | FastAPI; при старте `docker/backend-entrypoint.sh`: миграции Alembic с резервной копией → идемпотентный seed → uvicorn |
| `frontend` | 8501 (`FRONTEND_PORT`) | прежний Streamlit-интерфейс, ходит в `backend` по `API_URL` |

Образ `backend`/`frontend` — общий (`Dockerfile`, multi-stage, пользователь без root);
`web` собирается из `web/Dockerfile` в режиме `VITE_DATA_MODE=api`.
База — SQLite в томе `adler-data` (`/app/runtime/adler.db`, бэкапы в `/app/runtime/backups`).
Порядок старта: `backend` healthy → `web` и `frontend`. У всех есть healthcheck.

Общие ML-настройки команды лежат в [`config/models.yaml`](config/models.yaml):
режим, имена моделей, температура, контекст, лимит ответа, таймаут. Веса скачиваются отдельно
и не входят в Git/образ. Подробности: [настройка модели](docs/MODEL_CONFIGURATION.md), [DOCKER](docs/DOCKER.md).

В `.env.example` — только окружение и секреты: порты, `DOCKER_PARSER_MODE`, `REPLY_PARSER_MODE`,
`DOCKER_OLLAMA_URL` (по умолчанию `http://host.docker.internal:11434`), пустые места для
`GROQ_API_KEY`/`OPENAQ_API_KEY`. Свой `.env` не коммитьте. Ollama не открывайте в публичный интернет.
Скрытого переключения при ошибке модели нет.

## Сидирование

Выполняется автоматически при старте `backend` (после миграций; идемпотентно: ответы отельера
не стираются, дубликатов нет). Вручную:

```bash
docker compose exec backend python -m scripts.seed_demo
```

Демо-данные — `data/demo/` (отели, маршруты, наблюдения) и `data/environment/` (здания, береговая линия,
рельеф Copernicus, ВПП). Пересбор из интернета (не нужен для демо) — раздел «Проверки и обновление данных».

## Маршруты/доступ

- `http://localhost:8080/` — React-интерфейс: поиск, выдача с картой, карточка отеля, кабинет отельера (`/hotelier`)
- `http://localhost:8501/` — Streamlit (поиск, кабинет, конфликты, среда вокруг отеля)
- `/health` — `200 OK`, JSON `{"status": "ok", "hotels": 25}` (`503 {"status": "needs_seed"}`, если база пуста)
- `/api/health`, `/api/search`, `/api/parse-query`, `/api/hotels`, `/api/hotels/{id}/evidence`,
  `/api/hotelier/...` — REST API, подробно в [docs/API.md](docs/API.md)
- `/docs` — Swagger UI (на 8080 через прокси и на 8000 напрямую)
- Авторизации нет: кабинет отельера — локальная демонстрация, тестовые учётные данные не нужны.

## О проекте

Обновление 26 октября: [NoiseModelling/OpenAQ и проверка Адлера](docs/ENVIRONMENT.md),
[облачные модели и ранжирование v2](docs/MODELS_AND_RANKING.md).
Для сохранённых отчётов среды: `python -m scripts.seed_demo --environment`.
Для облачной LLM нужен личный Groq Free Plan key; профили 20B/27B/120B ещё
**не сравнивались на реальной генерации**. Текущий общий режим — Ollama; офлайн-разбор доступен через `PARSER_MODE=offline`.
Акустика на реальной геометрии пока представляет явно помеченный учебный сценарий.

Актуальный проект расположен **в корне репозитория**. Запускайте backend через
`app.main:app`. Старая вложенная копия `Островок/` удалена при очистке 29.10.2026.
Корневой `main.py` содержит сохранённые учебные заглушки f/y и не используется при запуске.

Работающий локальный MVP: русский запрос → типизированные условия → выбор источника агентом →
пешие маршруты/шумовой proxy → подбор с объяснениями → диалог с демонстрационным отельером.

Подготовлены **25 реальных OSM-отелей** и **400 наблюдений** по 16 характеристикам из открытых данных — у каждого
источник, дата, срок годности, уверенность и человеческое объяснение. Что считается по геоданным:

| Что | Как | Пример объяснения |
|---|---|---|
| Вид на море, закат, горы по этажам и сторонам | лучи из окон по рельефу Copernicus + высотам зданий OSM, солнце NOAA по месяцам | «Закат из окон стороны З, с 2-го этажа, круглый год; солнце садится в море» |
| Путь до пляжа и его качество | пешеходный граф OSM, подъёмы по рельефу, переходы через трассы с типом перехода | «1 переход через оживлённые дороги: улица Ленина (нерегулируемый)» |
| Тишина и авиашум | дороги/ж/д/бары OSM; траектории ВПП Сочи с глиссадой 3° | «траектория… проходит ≈ в 78 м от окна 3-го этажа» |
| Шум по сторонам здания | те же источники для каждой стены, экранирование своим и соседними домами | «Тихая сторона — ЮЗ, экранирует своё здание; шумная — СВ: улица Ленина, 13 м» |
| Что работает ночью | `opening_hours` OSM, открыто в 01:00 все 7 дней | «Ночью открыто в 500 м: супермаркет «Гастроном» 66 м…» |

Расчёт сверен с отзывами гостей и **реальными фото** балконов и фасадов (`python -m scripts.evaluate_viewshed`,
`python -m scripts.evaluate_photos`, [VALIDATION](docs/VALIDATION.md)): по фото найдены и исправлены неверная
этажность в OSM, обрезанные горы и отсутствие деревьев; уличные деревья у домов пока не учитываются.
Вид и закат пересчитываются, если в OSM появился новый дом (`scripts/refresh_geo.py`).
Какой номер куда выходит — вопрос отельеру; его ответ сверяется с расчётом. Все ответы локального
кабинета — **симуляция** и по умолчанию исключены из подбора. Это не сервис бронирования и не интеграция с API Островка.

## Запуск через Docker Compose

```bash
docker compose up --build --detach --wait
```

React: <http://localhost:8080>, Streamlit: <http://localhost:8501>, API/Swagger: <http://localhost:8000/docs>.
Миграции и seed выполняются автоматически; SQLite сохраняется в Docker volume.
Остановка: `docker compose down` — данные сохраняются.
Настройки ML, порты и команды: [DOCKER](docs/DOCKER.md).

## Запуск без Docker

Проверено на macOS arm64, Python **3.12.7** (этапы backend) и **3.13.5** (исходное демо).
Используйте Python 3.12+.
Запускайте команды из корня проекта. При первой установке нужен интернет; для поиска после установки — нет.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -c requirements.lock -e '.[test]'
python -m scripts.migrate_db
python -m scripts.seed_demo
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Во втором терминале из этой же папки:

```bash
source .venv/bin/activate
python -m streamlit run frontend/app.py --server.address 127.0.0.1 --server.port 8501 --server.headless true --browser.gatherUsageStats false
```

Интерфейс: <http://127.0.0.1:8501>. Swagger: <http://127.0.0.1:8000/docs>.
API: <http://127.0.0.1:8000/api/health>. Оба процесса останавливаются `Ctrl+C`.
`seed_demo` идемпотентен: не удаляет ответы и не создаёт дубликаты. Файл SQLite: `runtime/adler.db`.
Чтобы начать новое демо, задайте другой `DATABASE_URL`, затем снова выполните seed; не удаляйте чужую базу.

`.env` не обязателен. При необходимости скопируйте `.env.example` в `.env`.
Ключи/API Островка не нужны. Для полной офлайн-демонстрации есть встроенная SVG-схема без подложки.
Дополнительная Folium-карта требует интернета для CDN/тайлов и включается отдельным переключателем.

## Обновление SQLite и подключение участников

Перед обновлением существующей базы остановите backend и выполните
`python -m scripts.migrate_db`. Команда создаёт проверенную резервную копию
в `runtime/backups/`, проверяет известную схему и применяет миграции Alembic.
Повторный запуск сохраняет данные. Подробности: [MIGRATIONS](docs/MIGRATIONS.md).

Решение конфликта уже доступно через API и учитывается поиском, агентом и evidence.
Для экрана есть настоящий HTTP-клиент и явная заглушка без сервера;
для ML сохранены существующие форматы с необязательным контекстом конфликтов.
Примеры подключения: [CONFLICT_INTEGRATION](docs/CONFLICT_INTEGRATION.md).
В текущем Streamlit есть выбор версии и причины решения; очередь, история и
поиск обновляются после сохранения. [Контракт API и инструкция](docs/API_FRONTEND_INTEGRATION.md).
Вопрос повторно открывается при конфликте или устаревании, сохраняя историю;
фильтры очереди и заглушки её состояний: [QUESTION_INTEGRATION](docs/QUESTION_INTEGRATION.md).
Разбор ответа отельера заменяется отдельно от гостевого parser через
`REPLY_PARSER_MODE=rules|fixture|ollama|groq`. По умолчанию остаётся offline rules.
Контракт ML, режим заглушки и ошибки: [REPLY_PARSER_INTEGRATION](docs/REPLY_PARSER_INTEGRATION.md).
Настоящая генерация ответов отельера на текущем окружении ещё не проверялась.

## Сценарий для жюри

1. Выберите первый пример: «Ищу тихий отель в Адлере, не дальше 500 метров пешком от пляжа, хотелось бы вид на море».
2. Нажмите «Найти отели». На сохранённом срезе: 12 соответствуют оценочному расстоянию, 1 требует уточнения, 12 исключены.
3. Откройте источники: увидите OSM ID, дату, метод, ограничения, `low`/`unknown`, исходный маршрут.
   К «вид на море» и «тихий» поиск сам добавил расчёт по геоданным: вид из окон здания
   («стороны ЮЗ, с 3-го этажа») и расстояние до траектории самолётов — у них свои слайдеры.
4. В «Отельер · демо» выберите вопрос о виде и ответьте: «В номерах 301–305 вид на море, все на 3-м этаже».
5. Проверьте структуру и подтвердите. До подтверждения факты не используются.
6. Включите «Учитывать симулированные ответы» и повторите поиск. Утверждение относится только к указанным номерам.
7. Разберите и подтвердите ответ на тот же вопрос «В номере 302 нет вида на море». Появится конфликт для 302; обе версии останутся в истории.
8. В «Противоречия» выберите версию, укажите причину и нажмите «Сохранить решение». Подбор и история обновятся автоматически.
9. Измените веса предпочтений и сравните до трёх отелей.
10. Для «Офелии» ответьте «В номере 201 вид на море, это 2-й этаж». По расчёту море видно с 3-го:
   ответ сохранится, но в кабинете и в поиске появится пометка о расхождении с расчётом.
11. Напишите свой запрос, например «Тихий отель у моря без баров, подальше от самолётов, чтобы не переходить трассу».
    Ключ LLM не нужен; слова, которые система не знает, будут показаны как «не учтено».
12. В кабинете раскройте «Вид на море из окон», выберите «Исправить» → «море в просвете». Появится конфликт;
    выберите верную версию и причину — решение сохранится вместе с историей.
13. Актуализация: `docker compose exec backend python -m scripts.refresh_geo --simulate-building 43.42503,39.91437,12`
    («построили» 12-этажный дом перед Cascade) → у Cascade и Golden Tennis Club закат «круглый год» станет
    «по сезонам», а «Черномор» потеряет единственный просвет на море с 4-го этажа.

В React-интерфейсе (http://localhost:8080) тот же путь по макету: запрос «Нужен номер со шторами blackout,
магазин ночью и море пешком» → «Шторы blackout — нет данных» → «Запросить у отельера» → кабинет
`/hotelier` → ответ «В номерах 301–305 есть шторы blackout…» → проверка → публикация → отель в выдаче
с «Шторы blackout — есть в номере 301». Подробно: [web/README.md](web/README.md).

Сценарий расширения «Нужен номер с плотными шторами» и подключение нового
свойства без ветвлений в агенте/хранилище/ранжировании: [этап 6](docs/REGISTRY_EXTENSION.md).

Повторяемая приёмка на отдельной SQLite: `python -m scripts.verify_backend`.
Результаты, точки подключения frontend/ML и оставшиеся проверки:
[BACKEND_HANDOFF](docs/BACKEND_HANDOFF.md).

Оценка 1.0 означает совпадение **известных мягких пожеланий**, а не «отель подходит на 100%».
Рядом всегда показывается покрытие, сортировка использует `score × coverage`.

## Парсер и границы готовности

Альтернативный режим `PARSER_MODE=offline` — **свободный текст без ключей и сети**: 15 демо-формулировок
(список в UI и `/api/demo-queries`) дают эталонный разбор, любой другой текст разбирается правилами
`app/ml/rules_parser.py` по словарю `query_patterns` из реестра. Понимает тишину и шум, пляж и расстояния
(«не дальше 1,5 км», «между 300 и 800 м», «10 минут пешком» = 800 м), вид на море и закат, бары,
самолёты, шумоизоляцию, отрицания («без баров», «не хочу рядом с барами»), «обязательно»/«желательно»,
«X важнее Y», «с весом 0.3». Цена, бассейн, даты, другой город не отбрасываются молча — система
просит их убрать. Это **правила, а не NLP-модель**: на 32 held-out запросах первый прогон дал
F1 по полям 0.65 (точное совпадение 0.41), после исправления общих ошибок — 0.95 / 0.72
(оптимистично: исправлялось с оглядкой на held-out). Подробно — [VALIDATION](docs/VALIDATION.md).
`PARSER_MODE=fixture` — только 15 демо-формулировок, остальное требует уточнения.

Общая модель и параметры задаются в `config/models.yaml`. В локальном `.env`
можно задать `OLLAMA_URL=http://127.0.0.1:11434` (адрес inference-сервера).
После `ollama pull gemma3:12b` и запуска Ollama перезапустите backend.
28 октября Gemma 12B проверена двумя реальными запросами: поиск 18.94 с и разбор
условия «не ближе 300 м» 5.85 с. Это smoke-проверка, не оценка качества на gold.
Ollama получает JSON Schema и 2 few-shot примера; ответ проверяется Pydantic.
Ошибки не заменяются выдуманными фильтрами.
В Docker по умолчанию `PARSER_MODE=offline` (`DOCKER_PARSER_MODE` в `.env`).
См. [официальную документацию structured outputs](https://docs.ollama.com/capabilities/structured-outputs).

Отельер использует ограниченный offline-парсер простых предложений: номера, диапазоны, булево свойство, отрицание, этаж.
Сезонность, исключения, «во всех номерах» без номеров требуют уточнения. Реальной авторизации/отправки сообщений нет.

## Проверки и обновление данных

```bash
python -m pytest
python -m scripts.validate_data
python -m scripts.evaluate_parser --mode offline
python -m scripts.evaluate_viewshed
# Только при доступной модели:
python -m scripts.evaluate_parser --mode ollama
```

Отдельная онлайн-подготовка (не нужна для демо):

```bash
python -m pip install -c requirements.lock -e '.[geo,test]'
python -m scripts.collect_adler_osm
# Для новой выгрузки вместо сохранённой: добавьте --refresh
python -m scripts.collect_environment_osm      # здания
python -m scripts.collect_viewshed_inputs      # береговая линия + рельеф Copernicus
python -m scripts.collect_aircraft_inputs      # ВПП аэропорта
python -m scripts.collect_amenities_osm        # заведения с opening_hours
python -m scripts.compute_geo_features
python -m scripts.validate_data
python -m scripts.seed_demo
```

Не запускайте сбор параллельно с записью тех же файлов. Обновление может изменить выборку и результаты поиска.
Сохранённые сведения имеют TTL; после его истечения они перестанут подтверждать условия. Повторный seed
не делает их свежими. Живой поиск не обращается к Overpass; агент сообщает о необходимости обновить snapshot
и даёт команду `python -m scripts.refresh_geo --refresh`: она сравнит здания, найдёт затронутые отели
и покажет «было → стало» (`--apply` записывает новый снимок; старые значения заменяются, а не конфликтуют).
